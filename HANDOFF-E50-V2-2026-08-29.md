## Why E50-as-written is dead (do not re-derive, do not implement it)

The old E50 theory (exempt the DRAFT context from "frugal no_alloc
sizing") is disproven by the logs:

1. `no_alloc = 0` for BOTH the target and the drafter at runtime:
   bench/logs/lane-AC1.log:116 (target, arch qwen35) and :329 (drafter,
   arch dflash). The flag is a fit/dry-run knob only
   (common/common.cpp:1713 -> src/llama.cpp:355 -> hparams; set by
   common/fit.cpp:55). The "frugal path"
   (src/llama-context.cpp:648-649,682-683,700,718-722: split_only +
   backend_buf_exp_size route, see ggml-backend.cpp:1907-1919 +
   ggml-alloc.c:950-959) NEVER executes in production. A draft
   exemption cparams flag is a no-op.
2. The DRAFT context is byte-identical fork-vs-stock: compute buffers
   415.14 / 371.27 / 363.77 / 9.39 MiB (ROCm0/ROCm1/Vulkan1/Host),
   graph nodes 711 (bs=384) / 611 (bs=1), splits 26 / 23, copies 1 -
   lane-AC1.log:439-445 vs lane-AE1.log:433-439. "Draft frugal
   reserve" is not the differentiator.
3. The divergence is the TARGET context compute buffer: fork 238.15 /
   245.65 / 238.15 MiB (+161.65 host, 4 splits) at c 200k
   (lane-AC1.log:246-251) vs stock 1302 / 1021 / 1332 MiB (journal
   E32; ~5.5x). Fork @250k is ~276/282/276 (E32).
4. Fork dflash2 vs stock 50f068fff (merge-base = 50f068fff; stock clone
   HEAD verified = 50f068fff detached) differs in 17 files. NO src-side
   reserve-sizing changes (llama-context.cpp diff = PP-restructure +
   DFLASH node count only; llama-model.cpp = COST split; llama.cpp =
   PP naming). The only code on the buffer/perf path is the fork's
   ggml-cuda Vega tuning:
   - ggml/src/ggml-cuda/fattn-tile.cuh   (+196)
   - ggml/src/ggml-cuda/mmq-config-vega.cuh (+270, new file)
   - ggml/src/ggml-cuda/top-k.cu         (+100, new file)
   - ggml/src/ggml-cuda/fattn.cu         (+53)
   - ggml/src/ggml-cuda/ggml-cuda.cu     (+5)
5. Perf shape fits a kernel/workspace theory, not draft sizing: base
   decode identical 6.9 = 6.9 t/s no-spec, same sha (E45); spec gain
   fork +30% vs stock +67% (E45); fork draft phase 22.97 s of a 115 s
   TG task, ~43 ms/round (E46); ~75 ms/round split-execution delta
   (E44, distinct figure - do not conflate).

Rejected alternatives (do not resurrect): draft no_alloc exemption
(no-op, findings 1-2); gallocr buffer-floor knob (adds slack, changes
neither packing nor workspace sizing; fattn.cu has no free-memory
heuristic to nudge - verified both trees); CPU drafter (AD3), CKPT=0,
checkpoints/cram, draft-device pinning (journal D/AD series).

## THE TASK: E50 v2 - compile-time gate on the Vega tuning, A/B it

Goal unchanged from E50: recover fork TG 9.0 -> ~11+ t/s @120k depth on
the champion config, everything else held fixed. Mechanism: build the
fork ONCE with the Vega tuning compiled out (= stock-equivalent kernels
and, expected, stock-like compute buffers), one user-run lane, read the
gate. Both outcomes are decisive:

- TG recovers -> the tuning is the cause -> bisect to the culprit file
  (Phase 5).
- TG does not move -> kernels AND buffers exonerated -> the delta is in
  meta-scheduler split execution -> rocprof repair (Phase 6, E49).

### Phase 1 (agent): the gate

- New cmake option `GGML_CUDA_VEGA_TUNE`, default ON (current behavior
  preserved bit-for-bit when ON).
- Wrap EVERY fork-added hunk in the 5 files above in
  `#if GGML_CUDA_VEGA_TUNE ... #else <stock code from 50f068fff> #endif`.
  The authoritative list of added lines is:
  `git diff 50f068fff dflash2 -- ggml/src/ggml-cuda/`
  (read it via the git tools; this diff is small, ~620 added lines).
  New files (mmq-config-vega.cuh, top-k.cu): gate at the include/compile
  site (CMakeLists compiles top-k.cu only when ON; guard the #include of
  mmq-config-vega.cuh at its include sites).
- MUST NOT touch anything outside those 5 files + the CMakeLists entry.
  MUST NOT change behavior of the default (ON) build.
- Comments 1-2 lines, non-obvious invariants only (AGENTS.md; the
  comment-checker hook fires on edits).
- Build both configurations as compile-QA (see Phase 2) before any lane.

### Phase 2 (agent): builds

- Do NOT reconfigure build-dflash (production binary stays tuned).
- Configure a new dir `build-dflash-novega`: replicate the flag set from
  build-dflash/CMakeCache.txt exactly (D11 recipe: CMAKE_HIP_COMPILER=
  /opt/rocm-6.1.0/lib/llvm/bin/clang + the six *_DIR package paths to
  /opt/rocm-6.1.0; GGML_CUDA_FA_ALL_QUANTS=ON, GGML_HIP_GRAPHS=ON,
  GGML_VULKAN=ON - uppercase) plus `-DGGML_CUDA_VEGA_TUNE=OFF`.
- Acceptance: both targets compile; `ldd` on the new llama-server shows
  ROCm 6.1 linkage (libhipblas.so.2, NOT .so.3 - wrong pin fails at
  start, D11/E31).

### Phase 3 (user runs; agent writes the scripts)

### Phase 4 (agent): gate analysis

Collect from lane-e50v2.log: target "compute buffer size" lines (expect
~1302/1021/1332 = stock-like in the OFF build - if still 238/246/238
the buffer delta is NOT the tuning; note it and proceed anyway, TG is
the gate), draft lines (expect unchanged 415/371/363), splits, TG@120k,
fill, repro-gate result, sha.

Gates:
- TG >= 10.5 -> Phase 5.
- 9.5 <= TG < 10.5 -> rerun the lane once (noise band), then decide.
- TG < 9.5 or repro gate fails -> Phase 6.

### Phase 5 (conditional): bisect the tuning

- Per-file sub-gates of GGML_CUDA_VEGA_TUNE (suggested order:
  fattn-tile first, then mmq-config-vega, then top-k / fattn.cu /
  ggml-cuda.cu), rebuild novega dir per variant, one lane each
  (LANE=e50v2-b1, -b2, ...). Binary search: 2-3 lanes, not 5.
- On culprit identified: STOP coding. Product decision is the user's
  (keep tuning for ctx mode vs speed mode; runtime-toggle refinement is
  a follow-up plan, not improvisation).
- Close out: journal E-entry (numbers + citations), update the affected
  launcher header comments (launchers are gitignored - on disk only,
  journal their content), commit
  `cuda : add GGML_CUDA_VEGA_TUNE gate (E50v2)` + `Assisted-by: <name>`,
  then `GIT_MASTER=1 git push gfx906 dflash2:master`. NEVER origin, no
  PRs/comments upstream (ban risk).
