# JOURNAL 2026-09-10

## Push unblock: GitHub 100MB limit (ops, not an experiment)

- Symptom: `git push gfx906 master` rejected by pre-receive hook.
  `bench/bin-baseline-mmq/libggml-hip.so.0.16.0` at 115.70 MB exceeds
  GitHub's 100 MB hard limit; blob entered history in the E139
  sync-completion commit (c84835a69) and was only tree-removed by the
  later "removed unneeded bloat" commit, which does not help a push.
  A 44 MB `libggml-vulkan.so.0.16.0` twin rode along (under limit, bloat).

- Root cause: `.gitignore` has `*.so` but not `*.so.*`, so versioned
  library names (`libggml-hip.so.0.16.0`) slip through.

- Fix:
  1. `pip install git-filter-repo`, then strip both blobs:
     `git filter-repo --force --invert-paths --path <hip>.so.0.16.0
     --path <vulkan>.so.0.16.0 --refs gfx906/master..master`
  2. `.gitignore`: added `*.so.*` after `*.so` (Extensions section).

- Verification:
  - `git diff backup/pre-blob-strip master` is empty: HEAD tree
    byte-identical to pre-rewrite.
  - Blob scan of gfx906/master..master: nothing over 20 MB remains.
  - 103 commits in range, merge-base == gfx906/master tip (f4a3841fa):
    push is a clean fast-forward.

- Known side effect: filter-repo's `--refs` range mode rehashed 102/103
  commits (incl. the 93 upstream commits of the 2026-09-09 sync, now
  content-identical twins). Next `git merge origin/master` resolves
  trivially since trees match. Rollback point: branch
  `backup/pre-blob-strip` holds the full pre-rewrite chain; delete it
  once the push is confirmed good.
