## E168 — prod logging: normal output + all tokens in/out, no -v

Task: prod launcher (2llama-start-iq6v_f16_f16.sh) must log ONLY what llama.cpp
normally outputs + all tokens going in and out, no verbose spam. Motivating
incident: an opencode TUI session died 2026-09-13 ~02:28 with no crash log
anywhere (no OOM, no core dump, no app error) — silent deaths left no trail.

### What stock provides
- `--log-file FNAME` (env LLAMA_ARG_LOG_FILE): common_log `print_entry()`
  tees every entry to stderr AND the file (common/log.cpp). DEBUG lines go to
  the file even when below the stderr threshold — so `-v` in the launcher
  would have flooded the log file too.
- `--log-prompts-dir PATH`: one .txt per request with the raw prompt
  (server-context.cpp handle_completions_impl) — tokens IN only; responses
  were not logged by stock.

### Fork patch (tools/server/server-context.cpp)
- New static `append_prompt_log_completion()`: appends `\n\n===== COMPLETION
  (N tokens) =====\n<ids>\n<text>\n` to the per-request prompt file.
- Called from both completion paths where the final result is observed:
  non-stream (`all_results.results` loop) and stream (`set_next` lambda,
  capture `prompts_log_file` by value — the local dies when
  handle_completions_impl returns, the lambda outlives it).
- Source of truth = `server_task_result_cmpl_final` (`content` + `tokens`),
  i.e. exactly what the model generated, before any res_type reformatting.
  Covers OAI chat/cmpl, non-OAI, Anthropic, Responses API alike.

### Launcher (2llama-start-iq6v_f16_f16.sh)
- Dropped `-v` (user's debug flag; it is the verbose spam and would also
  hit the log file).
- Added `--log-file $LOG_DIR/llama-server-iq6v-f16-f16.log` +
  `--log-prompts-dir $LOG_DIR/prompts`, `LOG_DIR` default
  `$SCRIPT_DIR/log` (override via env), `mkdir -p` for it.
- Log file is truncated per boot ("w" mode) — one file per server run;
  prompts dir accumulates per-request .txt (12-digit ms names).

  `bash -n` OK, `--help` shows both flags.
- Live verification pending: applies at next prod restart (server currently
