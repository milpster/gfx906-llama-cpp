## E176 - why-75 anatomy + model research (user: "read the changes, do research, why so slow in pp5712")

### Model (web: QwenLM/Qwen3.8-Flash-Next, tech report 2608.30320, HF card)
- 125B total / 6B active + 51B n-gram table ("PLE", layer 2, bigram/trigram,
  20M entries) + 2.6B MTP head (1 layer, reuses QSA indices)
- 48 layers = 12 x (3 GDN + 1 QSA); only 12/48 do attention; QSA budget K=2048
- 512 experts, 10 routed + 1 shared, intermediate 640; hidden 2560
- Community refs: DGX Spark (128GB UMA + NVMe): 76.7 t/s PP / 25 t/s TG.
  Single 24GB GPU + table streamed: 700 t/s PP @ub512. Decode scales with
  RAM bandwidth for CPU experts (~6 GB/token). ik_llama #2369 head-in-file
  MTP; mihailescu2m --moe-stream; nitinpanj v3: 95.5GiB on 64GB RAM rig.

### Why 75 t/s (anatomy, not knobs)
- ub5712 x 10 routed over 512 experts = ~100% expert coverage per layer
  per ubatch -> ~50 GB host->GPU staging EVERY ubatch: 15 s at 3.3 GB/s
  RAM-resident, up to 100 s cold-SATA. 75 t/s = mostly cold pages + churn
  (rep2 36 t/s proved), PLE SATA reads, draft prefill tax, 8-thread serve cap.
- Draft prefill tax confirmed in code: common/speculative.cpp process()
  runs llama_decode(ctx_dft) once PER MTP HEAD per prefill ubatch
  (for head < n_mtp_layers, line ~1715), serialized with main PP.
- Sync delta explained: #28501 (5c53396b8, only in 0920) fixed vulkan
  mul_mat_id row-id hoist 256->512 experts - "Flash-Next quietly on the
  slow path" = part of 58.95->75.10 build gap.

### Experiments this entry

  not just llama-cli; use [x] bracket pattern to avoid self-pkill).
- threads16 (mmap, 5928 tok): 54.67 rep1 / 36.25 rep2 - churn-dominated,

- sp-e148-repl (E148 lane + sidecars: ncmoe24, ot exps-only 24-35,
  ts70,10,20, threads16, KQ_MASK_GEN=2, 1x5712): VULKAN OOM (3.49 GB
  compute reserve + weights; exps-only keeps attn of 24-35 on GPU).
- sp-e148-repl2: same at ts68,12,20 - PAST the fit point, running.

### Lever queue (evidence-ranked)
1. E148-lane shape + threads16 + KQ_MASK_GEN=2 (running)
2. Draft-prefill skip/cap patch (MTP head needs only last ~2k positions:
   QSA K=2048; codebase treats draft-KV holes as supported degradation)
3. Expert-tail requant (skill): 50->35 GB streamed = floor 15->10.5 s
4. GGML_EXPS_GPUGATHER (+1.8% E159), warm-cache steady state
5. Hardware: 128 GB RAM + NVMe = the 700 t/s community lane
